# Локации — playbook для стола

Эталон: PDF **Камнеграда** (`examples/locations/kamnegrad-klinkerov.pdf`) — город, по которому уже водили.  
Цель скила: такой же **документ для ведения** (Markdown + **.docx** под Google Doc), не короткая wiki-карточка.

Перед работой — ритуал [`echo-dawn-canon`](../echo-dawn-canon/SKILL.md).

## Когда вызывать

- «Сделай / расширь локацию X»
- «Район / таверна / форт / данж-хук как playbook»
- «Выгрузка в docx для Google Doc»

Не использовать для: полного текста квеста (якорь + отдельный quest-скил), глав книг, артефактов.

## Масштаб (поступательно)

Локация = любой масштаб: **одна таверна** или **весь город**.

| Режим | Что генерить |
|---|---|
| **seed** | Титул, атмосфера, 5 фактов «сейчас», список районов/зон (заглушки) |
| **district** | Один район целиком: места + НПС + таблицы + якоря квестов |
| **site** | Одно место (трактир, ратуша, шахта…) на полную глубину |
| **expand** | Добрать следующий район/место по запросу мастера |

Не раздувать сразу весь город «как Камнеград», если не просили. Спросить масштаб, если неясен.

## Статус файлов

| Статус | Когда |
|---|---|
| `prep` | Заготовка до стола / пока не сыграли |
| `played` / хроника | После сессии: что реально случилось → ужать в wiki + timeline |
| `canon` (wiki-карточка) | Короткая ссылочная карточка в `world/locations/` — факты мира, подтверждённые мастером или игрой |

**Playbook** живёт в `campaign/prep/locations/<slug>/` как `prep`, пока события не прошли за столом.  
Заготовки не удалять — можно перешить позже.

## Выходные артефакты (обязательно)

```
campaign/prep/locations/<slug>/
  playbook.md          # полный текст для ведения
  playbook.docx        # то же для Google Doc (pandoc или python-docx)
  npc-registry.md      # реестр имён этой локации
  README.md            # масштаб, статус, что уже детализировано
```

Опционально позже: короткая `world/locations/<slug>.md` (wiki), когда мастер скажет «это в мире есть».

### Docx

После `playbook.md`:

```bash
pandoc campaign/prep/locations/<slug>/playbook.md -o campaign/prep/locations/<slug>/playbook.docx
```

Если нет pandoc — `python-docx` или сказать Игорю путь к `.md` и поставить pandoc в env. **Docs = цель.**

## Шаблон playbook

Копия-основа: [`templates/location-playbook.md`](../../../templates/location-playbook.md)

### Корень документа

1. Титул, регион, точка на карте, масштаб, `status: prep`  
2. Атмосфера (1 абзац)  
3. **5 фактов «сейчас»** (живой мир — что уже происходит без партии)  
4. Власть / фракции на месте  
5. Список районов или зон (оглавление)  
6. Сводный индекс НПС (ссылка на registry)  
7. Сводный индекс **якорей квестов** (не полные квесты)  
8. Что делает мир, если партия медлит  

### Район → Место

Для **каждого детализированного места**:

1. Кратко (что это, кто хозяин)  
2. **Случайные события — таблица 1к6** (обязательно)  
3. **НПС** (слоты ниже)  
4. **Якоря квестов** — id + одно предложение + кто может выдать; полный текст → скил [`echo-dawn-quest-side`](../echo-dawn-quest-side/SKILL.md) в `quests/` + обновление якоря здесь.

## Слоты НПС (максимальное погружение)

Для каждого НПС заполнять **все** поля (если поле «н/п» — явно написать):

| # | Поле |
|---|---|
| 1 | Полное имя (уникально в локации) |
| 2 | Мировоззрение |
| 3 | Профессия / роль |
| 4 | Что делает **здесь и сейчас** в этом месте |
| 5 | Внешность |
| 6 | Связи с другими НПС локации / города |
| 7 | Жизненная цель |
| 8 | Отношение к ключевым силам *(параметры локации: напр. Аэлендор, Хребет, Разлом — задать в шапке playbook)* |
| 9 | **Голос / манера речи** (темп, жаргон, жесты) |
| 10 | **Секрет от партии** (что скрывает) |
| 11 | **Что даст / попросит** за помощь или сделку |
| 12 | **Бой:** CR / ключевые статы или «не боевой»; D&D **5e (2014)** |

Не копировать шаблон «ещё один дварф-кузнец Торин» — каждый НПС должен отличаться целью, секретом и голосом.

## Уникальность имён (жёстко)

В пределах **этой локации** (весь playbook + registry):

1. **Полное имя** — только один раз.  
2. **Личное имя** (первое слово / имя до прозвища) — только один раз на локацию.  
   Нельзя: два «Торина», два «Сигрид» в одном Камнеграде.  
3. Перед добавлением НПС — проверить `npc-registry.md` и `rg` по папке локации.  
4. Дубликат = **ошибка**: переименовать до сохранения.

По всему канону мира уникальность «желательна», но **обязательна только внутри локации**.

## Квесты

Скил локации **не** пишет полные квесты.

В секции места — только **якорь**:

```markdown
### Якоря квестов
| id | Крючок | Кто может выдать | Связь с аркой? |
|---|---|---|---|
| q-kamne-01 | Пропажа груза синих камней | … | опционально |
```

Полный квест → скил `echo-dawn-quest-side` / `echo-dawn-quest-main` → дописывает файл квеста и строку в playbook.

## Случайные события

У **каждого** детализированного места — таблица **1к6**:

| 1к6 | Встреча | Механика / проверка (5e 2014) | Награда / последствия |
|---|---|---|---|

События должны отражать атмосферу места и живой мир (не дженерик «пьяница»).

## Система правил

Только **D&D 5-я редакция (2014)**. Не использовать термины/баланс 2024, пока мастер не скажет иначе.  
DC, действия, Condensed CR — в духе 2014 PHB/DMG.

## Живой мир

В шапке и в фактах «сейчас» всегда:

- что уже происходит без героев;  
- что усугубится, если они уйдут / промедлят;  
- минимум один фронт из `open-threads.md`, если локация в зоне войны/Разлома.
