# Postmortem · как создавалась книга Arc 3

Это не лор. Это **карта граблей**, чтобы следующий агент/чат не повторил месяцы боли заново.  
Продукт: `campaign/prep/arc3-visual-book/`. Заказчик: Игорь (GM/PM).

---

## Цель, как её поняли в итоге

Не «нагенерить красивых картинок в assets».  
А **вещь за стол**:

1. Открыл главу Preview → ведёшь сверху вниз.  
2. В нужный момент видишь лицо/место.  
3. Жмёшь **⬇** → фото на второй экран / планшет.  
4. Под портретом — что говорить этим голосом.  
5. Проверки читаются вслух по-русски.  
6. После двери — одна следующая глава; справочник (карты, вставки, playbook, spine) — в той же книге.

## Хронология пути (сжато)

### 1. Визуалы сессии 1

- Рефы фестиваля Лунного моста уже были → якорь стиля.  
- Похороны: тот же город, но белые ленты / пепел / тишина (**не** grimdark).  
- Серия funeral-a…f + промпты в `assets/prompts/lunnyy-most-arc3-s1.md`.

### 2. Планы NPC и локаций

- `arc3-npc-visual-plan.md` — кто face-to-face по дверям.  
- `arc3-location-visual-plan.md` — KEY-сцены.  
- Генерация порциями после ok мастера.  
- Источники скриптов — ветка `cursor/quest-skill-arc3-bd87` (квесты mq-01…06).

### 3. Первая «книга» и сломанные картинки

Много раундов «картинок нет»:

| Попытка | Почему умерла |
|---|---|
| Относительные пути разной глубины (`../`, `../../../`) | Preview резолвит не как файловая система агента |
| Папка `media/` + symlinks | Cursor/Git игнорируют или не отдают в preview |
| Встроить base64 data URI в md | Рендерер **выпиливает** data URI |
| Локальный HTTP / «скачай файл» | Мастер не должен быть CDN; путь не масштабируется |
| HTML INDEX с табами | Путаница вкладок, рассинхрон с md, «старый INDEX» |

**Победа:** публичный HTTPS (`https://iili.io/…` через freeimage.host). После этого мастер: «Ура! Появились картинки».

### 4. Надстройки UX (по запросам мастера)

После того как картинки ожили, пошли уточнения — каждое стало локом скила:

1. Описания персонажей / карточки → **галерея** (Кто / Зачем / Стоп).  
2. **Речь под каждым портретом**, не списком внизу.  
3. **⬇ скачать** на каждый кадр (второй экран).  
4. Проверки **по-русски** (Сл, Проницательность…).  
5. Дописать **все непрописанные двери** (не только A).  
6. Аудит дыр: карты, inserts, жертва, playbooks, spine, Гирмхельм, совет, дневник.  
7. Финал: **доделать всё**, но дневник — **только оглавление**.

### 5. Упаковка справочника (гл. 12–16)

- Locked-карты взяты с quest-ветки → `assets/maps/` → снова HTTPS.  
- Inserts mq-01/02/04 + sacrifice menu → одна глава.  
- Playbooks сжаты (Маяк, Причал 15 мест, Порог, Щит).  
- Spine mq-01/02 + доска Гирмхельма.  
- Совет: Малфурион + таймер ~1 мес. + Элессар как вторая ось.  
- Дверь B урезана: оболочка с.2 + TOC 58 стр. v3 / telegram-стиль.

## Что оказалось правильной архитектурой книги

```
README (3 шага)
  00 как вести
  01 до стола (слухи)
  02 хаб-сессия          ← главный вход за столом
  03–10 двери            ← ровно одна за вечер
  11 галерея             ← справочник лиц
  12–16 стол-справочник  ← карты / вставки / playbook / spine / локи
```

Скрипт двери **самодостаточен** на вечер, но в чеклисте указывает «дальше гл.N».

`image-urls.json` — единый реестр ключ→HTTPS (в т.ч. дубли `.jpg`/`.png` на один URL).

---

## Эмоциональный контракт с мастером

- Не обещать «картинки работают», пока не проверен HTTPS.  
- После фикса превью — явно: **закрой старые вкладки**.  
- Не размазывать продукт по 10 папкам без оглавления.  
- Когда мастер говорит «это всё очень важно» — закрывать **дыры аудита**, а не полировать уже живое.  
- Когда говорит «X пока не продумывай» — **заглушка**, не «чуть-чуть прозы».

## Метрики «книга готова»

- Мастер открыл гл.2 Preview и увидел кадры без плясок.  
- Может скачать лицо на планшет одной ссылкой.  
- Может провести любую дверь с.2 по одной главе.  
- Знает, куда смотреть после клиффа (spine/карты/вставки).  
- Не получает противоречия имён (Милана).
